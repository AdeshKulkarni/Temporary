# Database Data Dictionary: Voucher Management System

This document outlines the schema design, tables, constraints, data types, and min/max lengths for the core Voucher System.

---

## 1. `JS_EOD_MASTER`
**Description:** A single-row configuration and tracking table used to manage End of Day (EOD) batch statuses and system-wide synchronization flags.

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `ID` | NUMBER | 1 digit | Primary Key. Forced to 1 via check constraints to maintain a single row. | Yes | `1` | Yes |
| `JS_STATUS` | NUMBER(1,0) | Exact 1 digit | Global application/service availability flag. | No | `1` | No |
| `EOD_STATUS` | NUMBER(1,0) | Exact 1 digit | Flag indicating if End of Day processing is active. | No | `0` | No |
| `JS_UPDATED_AT` | TIMESTAMP(6) | Fixed | Timestamp of the last application status change. | No | *None* | No |
| `EOD_UPDATED_AT` | TIMESTAMP(6) | Fixed | Timestamp of the last EOD operation. | No | *None* | No |
| `JS_PENDING_COUNTER` | NUMBER | Max 28 digits | Tracks active jobs pending before EOD can safely run. | No | `0` | No |

## 2. `REQUEST_VOUCHER`
**Description:** The core master table for Voucher IDs (VIDs). Tracks the creation, authorization, and lifecycle status of a VID before actual financial batches are attached to it.

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `ID` | NUMBER | 1 - 28 digits | Internal Sequence Identity Primary Key. | Yes | *Auto-Identity* | Yes |
| `VID` | VARCHAR2(20) | Max 20 chars | The alphanumeric business identifier (e.g., `VID-2610-00001`). Generated by Database Trigger. | Yes | *Trigger* | Yes |
| `CATEGORY_ID` | NUMBER | 1 - 28 digits | Foreign key linking to the `VOUCHER_CATEGORY` table. | Yes | *None* | No |
| `DESCRIPTION` | VARCHAR2(500) | 1 - 500 chars | The business justification provided by the creator. | Yes | *None* | No |
| `ALLOWED_ROLE` | NUMBER | 1 - 28 digits | The Security Role ID permitted to process batches under this VID. | Yes | *None* | No |
| `SD_REQ_NO` | VARCHAR2(100) | 0 - 100 chars | External integration reference (e.g., Service Desk Ticket Number). | No | *None* | No |
| `CREATED_BY` | VARCHAR2(100) | 0 - 100 chars | User ID of the administrator who created the VID. | No | *None* | No |
| `CREATED_AT` | TIMESTAMP(6) | Fixed | Audit timestamp of VID creation. | No | `CURRENT_TIMESTAMP` | No |
| `TERMINATED_BY` | VARCHAR2(100) | 0 - 100 chars | User ID who manually closed or exhausted the VID. | No | *None* | No |
| `TERMINATED_AT` | TIMESTAMP(6) | Fixed | Audit timestamp of closure. | No | *None* | No |
| `STATUS` | VARCHAR2(30) | 1 - 30 chars | Lifecycle state (e.g., `ACTIVE`, `USED`). | Yes | *None* | No |
| `REMARKS` | VARCHAR2(500) | 0 - 500 chars | Closure or administrative remarks. | No | *None* | No |
| `BACK_DATE` | DATE | Fixed | Authorized business backdate (if granted). | No | *None* | No |
| `IS_BACK_DATED` | NUMBER(1,0) | Exact 1 digit | Boolean configuration flag (0/1) for backdating permissions. | Yes | `0` | No |

## 3. `VOUCHER_CATEGORY`
**Description:** A lookup table defining the high-level financial groupings (categories) available when creating a new Voucher ID.

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `ID` | NUMBER | 1 - 28 digits | Internal Identity Primary Key. | Yes | *Auto-Identity* | Yes |
| `CATEGORY_NAME` | VARCHAR2(20) | 1 - 20 chars | The descriptive name of the category. | Yes | *None* | Yes |
| `CREATED_DATE` | TIMESTAMP(6) | Fixed | Audit timestamp. | No | `CURRENT_TIMESTAMP` | No |

## 4. `ISSUE_CATEGORY`
**Description:** A lookup table defining sub-issues or operational tags mapped to specific Voucher Categories.

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `ID` | NUMBER | 1 - 28 digits | Primary Key. | Yes | *None* | Yes |
| `VOUCHER_CATEGORY_ID` | NUMBER | 1 - 28 digits | Foreign Key linking to parent `VOUCHER_CATEGORY`. | Yes | *None* | No |
| `ISSUE_CATEGORY_NAME` | VARCHAR2(100) | 1 - 100 chars | The descriptive name of the issue tag. | Yes | *None* | No |
| `CREATED_DATE` | TIMESTAMP(6) | Fixed | Audit timestamp. | No | `SYSTIMESTAMP` | No |

---

## 5. `REQUEST_VOUCHER_ISSUE_CATEGORY`
**Description:** A mapping (join) table allowing a single Request Voucher (VID) to be tagged with multiple Issue Categories.

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `ID` | NUMBER | 1 - 28 digits | Primary Key. | Yes | *None* | Yes |
| `REQUEST_VOUCHER_ID` | NUMBER | 1 - 28 digits | Foreign Key mapping to `REQUEST_VOUCHER`. | Yes | *None* | No |
| `ISSUE_CATEGORY_ID` | NUMBER | 1 - 28 digits | Foreign Key mapping to `ISSUE_CATEGORY`. | Yes | *None* | No |

## 6. `VOUCHER_POSTING`
**Description:** The parent tracker table for an entire batch of uploaded or manually entered financial transactions. Maps the workflow lifecycle of a specific draft.

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `BATCH_ID` | VARCHAR2(50) | 1 - 50 chars | Unique Batch Identifier. Primary Key. | Yes | *None* | Yes |
| `VID_FK` | VARCHAR2(20) | 1 - 20 chars | The `VID` this batch is fulfilling. | Yes | *None* | No |
| `WORKFLOW_CODE` | VARCHAR2(100) | 0 - 100 chars | Identifies the specific routing chain (e.g., `Workflow_3`) used for approval. | No | *None* | No |
| `CREATED_BY` | VARCHAR2(100) | 0 - 100 chars | User ID of the Maker who drafted the batch. | No | *None* | No |
| `CREATED_AT` | TIMESTAMP(6) | Fixed | Audit timestamp of draft creation. | No | `CURRENT_TIMESTAMP` | No |
| `PENDING_AT` | NUMBER | Max 28 digits | Points to the `WORKFLOW_ID` of the current step waiting for action. | No | *None* | No |
| `IS_EXECUTION_SCHEDULED`| VARCHAR2(3) | 2 - 3 chars | Indicates if execution is scheduled (`YES` or `NO`). Checked by DB constraints. | No | *None* | No |
| `SCHEDULED_TIME` | TIMESTAMP(6) | Fixed | The specific future timestamp chosen for core ledger execution. | No | *None* | No |
| `IS_SCHEDULE_OVERRIDE` | VARCHAR2(3) | 2 - 3 chars | Indicates if a Final Approver altered the Maker's original schedule (`YES`/`NO`). | No | *None* | No |
| `EXECUTED_AT` | TIMESTAMP(6) | Fixed | The real-world timestamp when the batch successfully hit the core ledger. | No | *None* | No |
| `BATCH_STATUS` | VARCHAR2(20) | 1 - 20 chars | High-level status (e.g., `P` for Pending, `R` for Rejected, `C` for Completed). | No | *None* | No |
| `RECORDS_COUNT` | NUMBER | Max 28 digits | Number of individual transactions/rows contained within this batch. | No | *None* | No |
| `COMMON_BATCH_REMARKS` | VARCHAR2(30) | Min 2, Max 30 | The shared justification applied to all rows in the batch by the Maker. | No | *None* | No |
| `CREATOR_ROLE` | NUMBER(10,0) | Max 10 digits | The Security Role ID held by the Maker at the time of creation. | No | *None* | No |
| `EXECUTOR_ID` | VARCHAR2(10) | 0 - 10 chars | User ID or System ID that triggered the final execution. | No | *None* | No |
| `FIX_TYPE` | CHAR(1) | Exact 1 char | System flag (e.g., `J` for Journal). | Yes | `'J'` | No |
| `TARGET_DATE` | DATE | Fixed | Target business posting date. | No | *None* | No |

## 7. `VOUCHER_POSTING_DATA`
**Description:** The granular line-item table containing every individual financial row (Debit or Credit) inside a batch. 

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `REQ_STATUS` | VARCHAR2(10) | 1 - 10 chars | Row-level processing status (`P` = Pending, `A` = Approved, `R` = Rejected). | Yes | `'P'` | No |
| `REQ_DATE` | DATE | Fixed | Row creation/upload date. | Yes | `SYSDATE` | No |
| `CREATOR_ID` | VARCHAR2(12) | 1 - 12 chars | Maker User ID. | Yes | *None* | No |
| `EXECUTION_DATE` | DATE | Fixed | Timestamp applied when the row is successfully processed. | No | *None* | No |
| `BATCH_ID` | VARCHAR2(50) | 0 - 50 chars | Maps the row to its parent `VOUCHER_POSTING` batch. | No | *None* | No |
| `JOURNAL_ID` | VARCHAR2(50) | 0 - 50 chars | Logical grouping ID used to tie matching Debits and Credits together. | No | *None* | No |
| `REQ_BRANCH_CODE` | VARCHAR2(50) | 0 - 50 chars | Financial branch operating the entry (App limits to 5 digits). | No | *None* | No |
| `REQ_CURRENCY` | VARCHAR2(3) | Exact 3 chars | 3-letter currency code (e.g., `INR`, `USD`). | No | *None* | No |
| `REQ_CGL` | VARCHAR2(50) | 0 - 50 chars | General Ledger mapping code (App enforces exact 10-digits). | No | *None* | No |
| `REQ_AMOUNT` | NUMBER(25,4) | Max 21.4 digits| The transaction amount (Positive for Credit, Negative for Debit). | No | *None* | No |
| `REQ_NARRATION` | VARCHAR2(200)| 0 - 200 chars | Specific remarks for this distinct line item (App enforces 2-30). | No | *None* | No |
| `REQ_PRODUCT` | VARCHAR2(50) | 0 - 50 chars | Product classification code (App enforces max 8 digits). | No | *None* | No |
| `REQ_ID` | NUMBER(19,0) | 1 - 19 digits | Internal sequence primary key for the row. | Yes | *None* | Yes |
| `IS_CGL_VALID` | CHAR(1) | Exact 1 char | Post-validation tracking flag. | No | *None* | No |
| `IS_CURRENCY_VALID` | CHAR(1) | Exact 1 char | Post-validation tracking flag. | No | *None* | No |
| `IS_BRANCH_VALID` | CHAR(1) | Exact 1 char | Post-validation tracking flag. | No | *None* | No |
| `IS_VALIDATED` | CHAR(1) | Exact 1 char | Flag ensuring data passed security integrity checks before submission. | Yes | `'N'` | No |

| `TRANSACTION_ID` | NUMBER(20,0) | 1 - 20 digits | Primary Key sequence identifier. | Yes | *None* | Yes |
| `BATCH_ID` | VARCHAR2(50) | 0 - 50 chars | The source Batch ID. | No | *None* | No |
| `JOURNAL_ID` | VARCHAR2(50) | 0 - 50 chars | The source Journal Grouping ID. | No | *None* | No |
| `TRANSACTION_DATE` | DATE | Fixed | The actual business ledger date (derived from Fincore System date). | No | *None* | No |
| `POST_DATE` | TIMESTAMP(6) | Fixed | The literal wall-clock timestamp of when the row hit the ledger. | No | *None* | No |
| `BRANCH_CODE` | VARCHAR2(50) | 0 - 50 chars | Core Branch Code. | No | *None* | No |
| `CURRENCY` | VARCHAR2(3) | 0 - 3 chars | Core Currency. | No | *None* | No |
| `CGL` | VARCHAR2(10) | 0 - 10 chars | Core CGL. | No | *None* | No |
| `NARRATION` | VARCHAR2(40) | 0 - 40 chars | Core Remarks. | No | *None* | No |
| `DEBIT_AMOUNT` | NUMBER(25,4) | Max 21.4 digits| Calculated pure Debit Amount (0 if Credit). | No | *None* | No |
| `CREDIT_AMOUNT` | NUMBER(25,4) | Max 21.4 digits| Calculated pure Credit Amount (0 if Debit). | No | *None* | No |
| `TRANSACTION_COUNT`| NUMBER(10,0) | Max 10 digits | Number of distinct actions within the bundle. | No | *None* | No |

## 9. `VOUCHER_WORKFLOW`
**Description:** The absolute audit trail table. It records a permanent history log of every single human or system action taken on a Batch.

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `WORKFLOW_ID` | NUMBER | 1 - 28 digits | Identity Primary Key. | Yes | *Auto-Identity* | Yes |
| `BATCH_ID_FK` | VARCHAR2(50) | 1 - 50 chars | Foreign Key tying the event to a specific Batch. | Yes | *None* | No |
| `VID_FK` | VARCHAR2(20) | 1 - 20 chars | Tying the event to the parent VID. | Yes | *None* | No |
| `LAST_ACTION` | VARCHAR2(30) | 0 - 30 chars | Descriptive label of the event (e.g., `Final Approval`, `Execution Failed`). | No | *None* | No |
| `LAST_ACTION_BY` | VARCHAR2(100) | 0 - 100 chars | User ID (or `SYSTEM`) that triggered the event. | No | *None* | No |
| `LAST_ACTION_AT` | TIMESTAMP(6) | Fixed | Precise audit timestamp of the event. | No | `CURRENT_TIMESTAMP` | No |
| `REMARKS` | VARCHAR2(500) | 0 - 500 chars | The business justification entered by the user. | No | *None* | No |
| `SCHEDULED_TIME` | TIMESTAMP(6) | Fixed | Captures what execution time was selected during this specific action. | No | *None* | No |

## 10. `SCHEDULED_BATCH_RETRY`
**Description:** A recovery table. If the background scheduler attempts to execute a batch and the database throws a timeout, this table tracks the failure to safely retry it automatically up to 5 times.

| Column Name | Type | Length (Min/Max) | Purpose | Mandatory? | Default Value | Unique? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `BATCH_ID` | VARCHAR2(50) | 1 - 50 chars | The ID of the failed batch. | Yes | *None* | Yes |
| `CREATED_AT` | TIMESTAMP(6) | Fixed | When the failure was first tracked. | No | `SYSTIMESTAMP` | No |
| `RETRY_COUNT` | NUMBER | Max 28 digits | The number of attempts made so far. | No | `0` | No |
| `STATUS` | VARCHAR2(20) | 1 - 20 chars | Resolution status (`PENDING`, `COMPLETED`, `FAILED`). | No | `'PENDING'` | No |

| `BATCH_ID` | VARCHAR2(50) | 1 - 50 chars | The Batch ID pending synchronization. | Yes | *None* | Yes |
| `CREATED_AT` | TIMESTAMP(6) | Fixed | When the batch entered the queue. | No | `SYSTIMESTAMP` | No |
| `RETRY_COUNT` | NUMBER | Max 28 digits | The number of sync attempts made. | No | `0` | No |
| `STATUS` | VARCHAR2(20) | 1 - 20 chars | Sync Status (`PENDING`, `COMPLETED`, `FAILED`). | No | `'PENDING'` | No |
