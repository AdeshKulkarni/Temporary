I see exactly what is happening. The error you are getting ("File processing failed. Please ensure the file matches the expected format.") is being triggered by a highly restrictive regular expression validation on the filename when you try to upload it.
Issue 1: The Validation Error on Upload
In VoucherBulkValidationService.java, you have this check:
if (!filename.matches("^[a-zA-Z0-9_\\-\\s\\(\\)]+\\.(xlsx|xls)$")) {

This regex only allows letters, numbers, underscores, hyphens, spaces, and parentheses.
However, look closely at the filename in the image you provided: Error_Report - 2026-09-28T162857.948.xlsx.
It contains a dot (.) before the 948 (from the millisecond timestamp). The regex does not allow dots anywhere except right before the file extension (.xlsx). Because the filename has an extra dot, the regex rejects it and throws the generic "File processing failed" error.
The Fix: We need to update the regex to allow dots (.) in the filename.
Issue 2: Changing the Downloaded Error Report Name
You want the downloaded error report to be named something like Error_Report_BatchName.xlsx without the weird timestamp or gaps. In your code, you currently have:
String filename = "Error_Report_" + safeRequestId + ".xlsx";
(Where safeRequestId is the UUID of the request, which looks like a long random string).
To make it cleaner and match your requirement, we can append a clean timestamp string that looks like a batch name (e.g., Error_Report_20260928_1628.xlsx).
Here are the exact replacements for the two files to fix these issues.
1. Fix VoucherBulkValidationService.java
Find the initiateValidation method. We are going to update the regex to explicitly allow dots . and plus + signs, which are common in generated timestamps.
REPLACE THIS (Around line 102):
        // FIX 3: Add \\s (spaces) and \\(\\) (parentheses) to the regex so it accepts 'Template (1).xlsx'
        if (!filename.matches("^[a-zA-Z0-9_\\-\\s\\(\\)]+\\.(xlsx|xls)$")) {
            log.error("UPLOAD_SECURITY_DENIED | Status: Invalid characters or extension in filename");
            throw new CustomExceptions.FileProcessingException("Invalid file name. Only .xls and .xlsx files with alphanumeric characters, spaces, hyphens, underscores, and parentheses are allowed.");
        }

WITH THIS:
        // FIX: Added \\. to allow dots (e.g., from timestamps like 162857.948) in the filename
        if (!filename.matches("^[a-zA-Z0-9_\\-\\s\\(\\)\\.]+\\.(xlsx|xls)$")) {
            log.error("UPLOAD_SECURITY_DENIED | Status: Invalid characters or extension in filename");
            throw new CustomExceptions.FileProcessingException("Invalid file name. Only .xls and .xlsx files with alphanumeric characters, spaces, hyphens, underscores, dots, and parentheses are allowed.");
        }

2. Fix VoucherBulkUploadController.java
Find the downloadFile method. We are going to change how the filename variable is constructed so that it produces a clean, gapless name like Error_Report_Batch_20260928_1628.xlsx.
REPLACE THIS (Around line 90):
    @GetMapping("/download-bulk-file/{requestId}")
    public ResponseEntity<Resource> downloadFile(
            @PathVariable @Pattern(regexp = "^[a-zA-Z0-9-]{1,50}$", message = "Invalid ID") String requestId,
            @RequestParam @Pattern(regexp = "^[a-zA-Z0-9_]{1,20}$", message = "Invalid type") String type) {

        byte[] data = voucherBulkValidationService.getFileBytes(requestId, type);
        if (data == null) {
            log.warn("DOWNLOAD_FAIL | File not found | ReqID: {} | Type: {}", sanitizeLog(requestId), sanitizeLog(type));
            return ResponseEntity.notFound().build();
        }

        String safeRequestId = requestId.replaceAll("[^a-zA-Z0-9-]", "");
        String filename = "Error_Report_" + safeRequestId + ".xlsx";

        MediaType mediaType = MediaType.parseMediaType("application/vnd.openxmlformats-officedocument.spreadsheetml.sheet");

        return ResponseEntity.ok()
                .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=\"" + filename + "\"")

    }

WITH THIS:
    @GetMapping("/download-bulk-file/{requestId}")
    public ResponseEntity<Resource> downloadFile(
            @PathVariable @Pattern(regexp = "^[a-zA-Z0-9-]{1,50}$", message = "Invalid ID") String requestId,
            @RequestParam @Pattern(regexp = "^[a-zA-Z0-9_]{1,20}$", message = "Invalid type") String type) {

        byte[] data = voucherBulkValidationService.getFileBytes(requestId, type);
        if (data == null) {
            log.warn("DOWNLOAD_FAIL | File not found | ReqID: {} | Type: {}", sanitizeLog(requestId), sanitizeLog(type));
            return ResponseEntity.notFound().build();
        }

        // Generate a clean, continuous filename like "Error_Report_Batch_20260928_1628.xlsx"
        String timestamp = java.time.LocalDateTime.now().format(java.time.format.DateTimeFormatter.ofPattern("yyyyMMdd_HHmm"));
        String filename = "Error_Report_Batch_" + timestamp + ".xlsx";

        MediaType mediaType = MediaType.parseMediaType("application/vnd.openxmlformats-officedocument.spreadsheetml.sheet");

        return ResponseEntity.ok()
                .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=\"" + filename + "\"")
                .contentType(mediaType)
                .body(new ByteArrayResource(data));
    }

Why this fixes your issues:
 * No more upload errors: You can now upload Error_Report - 2026-09-28T162857.948.xlsx because the regex correctly permits the dot before the 948.
