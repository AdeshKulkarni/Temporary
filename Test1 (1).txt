Here is the step-by-step guide to resolve the ORA-02289 (Sequence does not exist) error and to rename the NotificationTable entity to Notifications.
🛠️ Step 1: Database Fixes (Execute in Oracle SQL Developer)
You must execute these SQL scripts to create the missing sequences and rename the table in your database.
1. Create the Missing Sequences
The error ORA-02289 happens because Java is looking for JOURNAL_REQUEST_SEQ, but it doesn't exist in the DB. Run this:
-- 1. Create Sequence for Journal Requests
CREATE SEQUENCE "FTWOAHM"."JOURNAL_REQUEST_SEQ" 
MINVALUE 1 
MAXVALUE 999999999999999999999999999 
INCREMENT BY 1 
START WITH 1 
NOCACHE 
NOORDER 
NOCYCLE;

-- 2. Create Sequence for Master Journal (if missing)
CREATE SEQUENCE "FTWOAHM"."MASTER_JOURNAL_SEQ" 
MINVALUE 1 
MAXVALUE 999999999999999999999999999 
INCREMENT BY 1 
START WITH 1 
NOCACHE 
NOORDER 
NOCYCLE;

-- 3. Ensure Batch and Journal Prefix sequences exist
-- (Only run these if you haven't already, or if you want to ensure they exist)
CREATE SEQUENCE "FTWOAHM"."BATCH_SEQ" MINVALUE 1 MAXVALUE 999999999 INCREMENT BY 1 START WITH 1 NOCACHE NOORDER NOCYCLE;
CREATE SEQUENCE "FTWOAHM"."JRNL_SEQ" MINVALUE 1 MAXVALUE 999999999 INCREMENT BY 1 START WITH 1 NOCACHE NOORDER NOCYCLE;

2. Rename/Create the Notifications Table
Run ONE of the following blocks (depending on if the old table exists or not).
Option A: If notification_table already exists and has data:
ALTER TABLE "FTWOAHM"."notification_table" RENAME TO "NOTIFICATIONS";

Option B: If the table does not exist (Create new):
CREATE TABLE "FTWOAHM"."NOTIFICATIONS" (
    "EVENT_ID" RAW(16) NOT NULL ENABLE, 
    "AGGREGATE_ID" VARCHAR2(255 CHAR), 
    "EVENT_SOURCE" VARCHAR2(100 CHAR), 
    "EVENT_TIMESTAMP" TIMESTAMP (6) NOT NULL ENABLE, 
    "LINK_URL" VARCHAR2(1024 CHAR), 
    "MESSAGE" VARCHAR2(1024 CHAR) NOT NULL ENABLE, 
    "TARGET_ROLE" VARCHAR2(100 CHAR), 
    "USER_ID" VARCHAR2(255 CHAR), 
    PRIMARY KEY ("EVENT_ID")
);

🛠️ Step 2: Java Code Updates
Here are the only files you need to update/rename to complete the NotificationTable \rightarrow Notifications change.
1. Rename NotificationTable.java to Notifications.java
Action: Rename the file in com.fincore.JournalService.Models and paste this code.
package com.fincore.JournalService.Models;

import jakarta.persistence.*;
import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Data;
import lombok.NoArgsConstructor;
import org.hibernate.annotations.CreationTimestamp;
import org.springframework.data.jpa.domain.support.AuditingEntityListener;

import java.io.Serializable;
import java.time.Instant;
import java.util.UUID;

@Entity
@Table(name = "NOTIFICATIONS") // Table name changed here
@Builder
@Data
@NoArgsConstructor
@AllArgsConstructor
@EntityListeners(AuditingEntityListener.class)
public class Notifications implements Serializable { // Class name changed to Notifications

    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    @Column(name = "EVENT_ID", updatable = false, nullable = false)
    private UUID eventId;

    @Column(name = "USER_ID", length = 255)
    private String userId;

    @Column(name = "MESSAGE", length = 1024, nullable = false)
    private String message;

    @Column(name = "LINK_URL", length = 1024)
    private String linkUrl;

    @Column(name = "EVENT_SOURCE", length = 100)
    private String eventSource;

    @Column(name = "AGGREGATE_ID", length = 255)
    private String aggregateId;

    @CreationTimestamp
    @Column(name = "EVENT_TIMESTAMP", nullable = false, updatable = false)
    private Instant eventTimestamp;

    @Column(name = "TARGET_ROLE", length = 100)
    private String targetRole;
}

3. Update NotificationWriterService.java
Action: Update the builder to use the new Notifications class.
package com.fincore.JournalService.Service;

import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Propagation;
import org.springframework.transaction.annotation.Transactional;

import com.fincore.JournalService.Models.Notifications; // Updated Import
import com.fincore.JournalService.Repository.NotificationRepository;

@Service
@RequiredArgsConstructor
@Slf4j
public class NotificationWriterService {

    private final NotificationRepository notificationRepository;

    @Transactional(propagation = Propagation.MANDATORY) 
    public void createNotification(String userId, String targetRole, String message, String linkUrl, String aggregateId, String eventSource) {

        if (userId == null && targetRole == null) {
            log.warn("Skipping notification creation: Both userId and targetRole are null. AggregateID: {}", aggregateId);
            return;
        }

        if (message == null || message.isBlank()) {
            log.warn("Skipping notification creation: Message is null or blank. AggregateID: {}", aggregateId);
            throw new IllegalArgumentException("Notification message cannot be null or blank.");
        }

        // Updated Builder to use Notifications
        Notifications notification = Notifications.builder()
                .userId(userId)
                .targetRole(targetRole)
                .message(message)
                .linkUrl(linkUrl)
                .aggregateId(aggregateId)
                .eventSource(eventSource)
                .build();

        notificationRepository.save(notification);

        if (userId != null) {
            log.info("Saved 1-to-1 notification event for user: {} (AggregateID: {})", userId, aggregateId);
        } else {
            log.info("Saved 1-to-many notification event for role: {} (AggregateID: {})", targetRole, aggregateId);
        }
    }
}

🛠️ Step 3: Verify and Run
 * Make sure you ran the SQL scripts from Step 1.

The ORA-02289 error will be gone because the sequence JOURNAL_REQUEST_SEQ now exists, and the application will now write notifications to the NOTIFICATIONS table.
