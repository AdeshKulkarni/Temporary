Exercise 15: Customer Support Ticket System
Problem: Create a support ticket system where customers can create tickets, and support agents can be assigned to resolve them. Track ticket status, priority, and assignment.

Ticket Statuses: OPEN, ASSIGNED, IN_PROGRESS, RESOLVED, CLOSED
Priority Levels: LOW, MEDIUM, HIGH, URGENT

Operations:

Customer "Alice" creates ticket T001 (Issue: "Login not working", Priority: HIGH)
Customer "Bob" creates ticket T002 (Issue: "Slow performance", Priority: MEDIUM)
Assign ticket T001 to Agent "Sarah"
Agent Sarah starts working on T001 (status: IN_PROGRESS)
Customer "Charlie" creates ticket T003 (Issue: "Feature request", Priority: LOW)
Assign ticket T002 to Agent "John"
Agent Sarah resolves T001
Show all tickets grouped by status
Show workload per agent (how many tickets assigned)
Output:

Ticket T001 created by Alice
  Issue: Login not working
  Priority: HIGH
  Status: OPEN

Ticket T002 created by Bob
  Issue: Slow performance
  Priority: MEDIUM
  Status: OPEN

Ticket T001 assigned to Agent Sarah
  Status: OPEN → ASSIGNED

Agent Sarah started working on T001
  Status: ASSIGNED → IN_PROGRESS

Ticket T003 created by Charlie
  Issue: Feature request
  Priority: LOW
  Status: OPEN

Ticket T002 assigned to Agent John
  Status: OPEN → ASSIGNED

Agent Sarah resolved T001
  Status: IN_PROGRESS → RESOLVED

Tickets by Status:
OPEN: 1 ticket
  - T003 (Charlie): Feature request [LOW]

ASSIGNED: 1 ticket
  - T002 (John): Slow performance [MEDIUM]

IN_PROGRESS: 0 tickets

RESOLVED: 1 ticket
  - T001 (Sarah): Login not working [HIGH]

CLOSED: 0 tickets

Agent Workload:
Sarah: 1 ticket (1 resolved, 0 active)
John: 1 ticket (0 resolved, 1 active)

Object state transitions (status changes)
Managing relationships (Ticket ↔ Customer, Ticket ↔ Agent)
Grouping objects by properties
Tracking multiple states
Agent workload calculation
