4. Voucher Posting and Batch Creation
(Roles: TCS GLIF, TCS IMPL)
Once an Administrator has successfully created an active Voucher ID (VID), it is time to add the actual financial transactions. This module explains how you can enter your data, validate it for errors, and schedule it for final execution.
4.1 Accessing Assigned VIDs
To start creating a voucher, you cannot just enter numbers blindly; you must first select an active VID from your assigned queue. Think of the VID as an approved empty folder waiting for your files.
￼ The One-to-One Rule: To prevent confusion and duplicate entries, the system strictly allows only one active batch of transactions to be tied to a single VID at a time.
￼ Reusability: If you make a mistake and decide to cancel or delete your draft before it gets approved, or if an Approver rejects it, don't worry! The system will automatically unlock that VID so you can use it again to create a corrected batch.
4.2 Selecting the Entry Method
Depending on how many transactions you need to process today, the system gives you two different ways to enter your data.
￼ Manual Entry: This is best for small, quick adjustments. It gives you an interactive grid right on your screen where you can type in the data row by row.
￼ Bulk Excel Upload: If you need to process hundreds or thousands of rows at once, this is the tool to use. You simply fill out a standardized Excel file offline and upload it all at once.
4.3 Method 1: Manual Voucher Entry
If you chose Manual Entry, you will see a grid on your screen. The system will guide you and check your work as you type.
4.3.1 Common Batch Remarks (Time Saver)
If all the transactions you are about to enter share the same reason or description, you don't need to type it over and over. You can type a "Common Batch Remark" at the top and check the box to automatically apply it to every row below.
￼ Rule to remember: Remarks must be between 2 and 30 characters long and can only contain letters, numbers, and single spaces between words.
4.3.2 Entering Transaction Rows
For every line item, you must fill out the following details:
￼ Branch & CGL (Mandatory): As you start typing the Branch Code or the General Ledger (CGL) number, a dropdown will appear. You can only select active codes that currently exist in the database.
￼ Currency (Mandatory): Select the correct currency from the dropdown list.
￼ Amount (Mandatory): Type the amount carefully. You can enter up to 16 digits and 4 decimal places. Important: You cannot enter negative numbers. If you need to reverse a transaction, simply enter a positive amount on the opposite side (for example, use a Credit instead of a Debit).
￼ Type (Mandatory): Select whether this specific row is a Debit or a Credit.
￼ Product Code (Optional): If your transaction requires a product classification, you can enter up to 8 digits here. Otherwise, you can leave it blank.
4.3.3 Grid Controls
At the bottom of the grid, you have simple tools to manage your workspace:
￼ Add Row: Adds a fresh, empty line to the bottom of your list.
￼ Delete Row: Removes a specific line if you made a mistake (Note: The system requires a minimum of two rows to balance a Debit and Credit).
￼ Reset: Clears the entire screen so you can start over from scratch.
4.3.4 Validation & Submission
When you are finished typing, click the Validate button. This is your safety net. The system will read all your rows to ensure that your total Debits perfectly match your total Credits, and that all branches are valid. You can only move to the final step if your batch passes this check with zero errors.
4.4 Method 2: Bulk Excel Upload
If you have a massive amount of financial data, typing it manually would take too long. The Bulk Upload tool handles this easily.
4.4.1 Downloading the Template
Always start by clicking the "Download Template" button on the screen. This ensures you are working with the exact format the system expects.
4.4.2 Formatting Rules
When you open the Excel file, you will see columns for Branch, Currency, CGL, Amount, Type, Remarks, and Product Code.
￼ Do not rearrange or delete these columns. The system reads them in this exact order.
￼ Fill out the sheet offline at your own pace. Columns with an asterisk (*) are mandatory.
4.4.3 Uploading and System Checks
Once your Excel file is ready, upload it to the system. The backend will immediately scan your entire file in three thorough stages to protect the ledger:
1. Checking for Typos: Ensures there are no letters inside the amount fields, and that remarks aren't too long.
2. Checking the Database: Cross-checks every single Branch and CGL in your file against the live master database to ensure they are active and valid.
3. Checking the Math: Calculates all your rows to guarantee that the total Debits perfectly equal the total Credits.
What happens if there is a mistake in the Excel file?
If you have 10,000 rows and even one row has an error, the system will reject the file to keep the ledger safe. However, it will automatically generate and download an Error Report Excel File for you. This brilliant feature highlights the exact row and tells you exactly what went wrong, so you can fix it quickly and re-upload.
4.5 Setting the Execution Schedule
Whether you used Manual Entry or Bulk Upload, your final step before submitting the batch to the Checkers is deciding when the money should actually move.
￼ Execute Immediately: Choose this if the transaction is urgent. As soon as the Final Approver clicks "Approve," the system will post the entries to the ledger right then and there.
￼ Schedule Execution: Choose this if you want to prepare the work now, but have the system wait to post it later (such as during off-peak hours or at the end of the day). You can pick any exact time today, starting from 30 minutes in the future up to 11:59 PM.
Once you select your schedule and click Submit, your job is done! The batch is now waiting in the Authorization queue for the Checkers.
