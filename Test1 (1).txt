I know exactly why both of these issues are happening!
1. Why you aren't getting the exact error message
The VoucherBulkValidationService is throwing the correct error message, but the Backend Controller is currently "swallowing" it and returning a hardcoded, generic response instead.
2. Why the filename has a dot (.854)
When the frontend forces the download, something in the browser or your environment is using a native ISO Date string (like 2026-09-28T17:59:02.854Z). Because you strip out the colons, it leaves the dot from the milliseconds, creating the ...175902.854.xlsx name.
Here is exactly how to fix both issues. You will need to change one block in the Backend and one block in the Frontend.
Fix 1: The Backend (To show the exact error message)
Open VoucherBulkUploadController.java and find the initiateValidation method. Look at the catch blocks at the very bottom of that method (around line 70).
REPLACE THIS:
        } catch (CustomExceptions.FileProcessingException e) {
            return ResponseEntity.status(org.springframework.http.HttpStatus.BAD_REQUEST)
                    .body(Map.of("message", "File processing failed. Please ensure the file matches the expected format."));

        } catch (java.io.IOException e) {

WITH THIS:
        } catch (CustomExceptions.FileProcessingException e) {
            // FIX: Pass the exact exception message (e.getMessage()) to the frontend 
            // instead of using a hardcoded generic string.
            return ResponseEntity.status(org.springframework.http.HttpStatus.BAD_REQUEST)
                    .body(Map.of("message", e.getMessage()));

        } catch (java.io.IOException e) {

Now, the UI will correctly display: "Files with multiple extensions are strictly prohibited."
Fix 2: The Frontend (To fix the automatic download filename)
Open VoucherBulkUpload.jsx and find the handleDownloadFile function (around line 195). We will use dayjs to explicitly format a clean filename without dots.
REPLACE THIS:
  const handleDownloadFile = async (type, reqId = requestId) => {
    if (type === "ERROR") showSnackBar("Downloading error report...", "info");
    const success = await downloadFileHelper(
      `/JS/voucher/download-bulk-file/${reqId}?type=${type}`,
      type === "ERROR" ? "Error_Report.xlsx" : ""
    );
    if (success && type === "SUCCESS") showSnackBar("Downloaded successfully.", "success");
    if (success && type === "ERROR") {
      setDownloadMsg("Error report downloaded.");
      setIsErrorDownloaded(true);
    }
  };

WITH THIS:
  const handleDownloadFile = async (type, reqId = requestId) => {
    if (type === "ERROR") showSnackBar("Downloading error report...", "info");
    
    // FIX: Explicitly format the date without dots or special characters!
    // Example output: Error_Report_20260928_1759.xlsx
    const cleanTimestamp = dayjs().format("YYYYMMDD_HHmm");
    const targetFilename = type === "ERROR" ? `Error_Report_${cleanTimestamp}.xlsx` : "";

    const success = await downloadFileHelper(
      `/JS/voucher/download-bulk-file/${reqId}?type=${type}`,
      targetFilename
    );
    
    if (success && type === "SUCCESS") showSnackBar("Downloaded successfully.", "success");
    if (success && type === "ERROR") {
      setDownloadMsg("Error report downloaded.");
      setIsErrorDownloaded(true);
    }
  };

Summary of what this does:
 * When you try to upload a file with an extra dot, the UI popup will now say exactly: "Files with multiple extensions are strictly prohibited."
 * When an error report downloads automatically, it will be named Error_Report_20260928_1759.xlsx. Because there is no longer a dot in the middle of the filename, if you fix the file and try to re-upload it, the system will accept it instantly!
