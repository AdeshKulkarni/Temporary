Based on the code I provided in the previous step (JournalBulkValidationService.java), here is the complete list of validations currently implemented.
They are categorized by Format (Syntax), System/CSV (Structure), and Database (Integrity), all of which are now checked simultaneously in the first stage.
1. General Field Validations (Applied to Excel & CSV)
These checks run on every row found in runDataValidation:
 * Branch:
   * Must not be Empty or Null.
 * Currency:
   * Must not be Null.
   * Must be exactly 3 Characters length (e.g., "USD", "INR").
 * CGL (General Ledger):
   * Must not be Empty.
   * Must match Regex: ^\d{10}$ (Exactly 10 Digits, numeric only).
 * Amount:
   * Must not be Null.
   * Must not be Zero (0).
   * INR Specific Rule: If Currency is "INR", the amount cannot have more than 2 decimal places.
 * Product Code:
   * If provided (not empty), it must be either:
     * The letter "A".
     * OR Exactly 8 Digits (Regex: ^\d{8}$).
2. CSV / System File Specific Validations
These checks happen during the parsing phase (parseCsvBytes and validateSystemColumns) if the file is detected as a System File (CSV/TXT):
 * Column Structure:
   * The row must have exactly 14 Columns.
 * Mandatory Data Missing:
   * Data cannot be empty for: Column 1 (BatchID), Col 5 (Branch), Col 6 (Currency), Col 7 (CGL), Col 8 (Amount).
 * Batch ID (Col 1):
   * Must be exactly '01'.
 * Date (Col 2):
   * Must match format ddMMyyyy (8 characters).
   * Must be a valid calendar date.
 * Financial Year & Month (Col 3 & 4):
   * Year Check: Must match the Financial Year derived from the Date (Col 2).
   * Month Check: Must match the Financial Month derived from the Date (Col 2).
 * Static Columns (Col 12, 13, 14):
   * Column 12 must be 'B'.
   * Column 13 must be 'C'.
   * Column 14 must be 'D'.
3. Database Integrity Validations
These run immediately alongside the format checks (provided the field isn't empty):
 * Branch Existence: The Branch code must exist in the BranchMaster table.
 * Currency Existence: The Currency code must exist in the CurrencyMaster table.
 * CGL Existence: The CGL number must exist in the CglMaster table.
4. Balance Validation (Stage 2)
This runs only if all the above validations pass:
 * Debit/Credit Match: The sum of Debits must equal the sum of Credits for every unique combination of Branch + Currency + Memo/Normal Type.
