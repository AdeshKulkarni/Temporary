I understand. You want to stop reading the user object manually from sessionStorage or localStorage using JSON.parse(), and instead use Redux's useSelector to grab the user seamlessly from your global state.
This is a much cleaner and more "React-way" of handling authentication data!
Here is exactly how to replace the old useEffect logic with your Redux state in the VoucherPosting.jsx file.
1. Extract the user directly from Redux
At the top of your VoucherPosting component (around line 143), right below where you already call useSelector for the menus, add the user selector.
FIND THIS:

2. Replace the ugly sessionStorage parsing
Now, scroll down to the two places where you are currently parsing sessionStorage manually. We will replace both of them with simple assignments using the Redux user object.
A. FIND THIS useEffect (Around line 192):
  useEffect(() => {
    isMounted.current = true;
    try {
      const auth = sessionStorage.getItem("persist:auth") || localStorage.getItem("persist:auth");
      if (auth) {
        const user = JSON.parse(JSON.parse(auth).user);
        if (user?.userId) setCurrentUserId(String(user.userId));
        // Assuming your auth object holds the role ID.
        if (user?.roleId) setCurrentRoleId(user.roleId);
      }
    } catch (e) { }
    return () => { isMounted.current = false; };
  }, []);

REPLACE IT WITH THIS CLEANER VERSION:
  useEffect(() => {
    isMounted.current = true;
    
    // Use the Redux 'user' object instead of parsing local storage!
    if (user) {
      if (user.userId) setCurrentUserId(String(user.userId));
      
      // Look for roleId or role or ROLE_ID based on your auth structure
      const actualRoleId = user.roleId || user.role || user.ROLE_ID;
      if (actualRoleId) setCurrentRoleId(actualRoleId);
    }
    
    return () => { isMounted.current = false; };
  }, [user]); // Add 'user' to the dependency array

B. FIND THIS inside fetchInitialData (Around line 210):
        // CRITICAL FIX: Synchronously extract the role directly from storage. 
        // Do not rely on 'currentRoleId' state here, as it will be 'null' on the first render.
        let actualRoleId = null;
        const auth = sessionStorage.getItem("persist:auth") || localStorage.getItem("persist:auth");
        if (auth) {
          const user = JSON.parse(JSON.parse(auth).user);
          // Checks multiple common property names just to be safe
          actualRoleId = user?.roleId || user?.role || user?.ROLE_ID;
        }

        if (!actualRoleId) {
          showSnackBar("User Role ID not found. Cannot fetch VIDs.", "error");
          setIsPageLoading(false);
          return; // Aborts the call if no role is found
        }

REPLACE IT WITH THIS CLEANER VERSION:
        // Grab the role synchronously directly from the Redux user object
        const actualRoleId = user?.roleId || user?.role || user?.ROLE_ID;

        if (!actualRoleId) {
          showSnackBar("User Role ID not found in session. Cannot fetch VIDs.", "error");
          setIsPageLoading(false);
          return; 
        }

Why this is better:
 * No more double parsing: JSON.parse(JSON.parse(auth).user) is notoriously slow and prone to crashing if the string is empty or malformed.
 * Instant Reactivity: Because user is tracked by Redux, if the user's role suddenly updates in the global state, this component will immediately re-render with the new role!
 * Cleaner Code: It removes about 15 lines of messy string-manipulation code.
