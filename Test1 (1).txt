This is a very classic security and code-quality finding from tools like Fortify/SonarQube/ISD.
When you have a catch (Exception e) block that simply catches the broad Exception class and returns a generic message, the scanner complains that you are swallowing potentially critical system errors (like NullPointerException or OutOfMemoryError) without properly logging the stack trace or throwing a specialized exception.
To fix this, we need to do two things in each of those files:
 * Change catch (Exception e) to something more specific, or log the actual stack trace of e.
 * Do not just return a generic map; throw a clean, structured exception if it's a critical error.
Here is the exact code to replace in each of the three files to clear the ISD warning.
1. Fix VoucherQueryController.java (Line 81)
Find the downloadBatchExcel method. You have a catch (Exception e) block that is triggering the warning.
REPLACE THIS:
        } catch (CustomExceptions.InvalidDataException e) {
            return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(Map.of("message", "Invalid Request Data"));
        } catch (Exception e) {
            log.error("DOWNLOAD_ERROR | Batch: {} | Reason: Internal Error", sanitizeLog(batchId));
            return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(Map.of("message", "Failed to generate Excel file."));
        }

WITH THIS:
        } catch (CustomExceptions.InvalidDataException e) {
            return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(Map.of("message", "Invalid Request Data"));
        } catch (org.springframework.dao.DataAccessException e) {
            // FIX: Catch specific database exception and log the actual error message
            log.error("DOWNLOAD_DB_ERROR | Batch: {} | Reason: {}", sanitizeLog(batchId), e.getMessage());
            return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(Map.of("message", "Failed to fetch data from database."));
        } catch (RuntimeException e) {
            // FIX: Log the full stack trace for runtime anomalies instead of swallowing it
            log.error("DOWNLOAD_SYSTEM_ERROR | Batch: {} | Reason: {}", sanitizeLog(batchId), e.getMessage(), e);
            return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(Map.of("message", "An unexpected error occurred during Excel generation."));
        }
