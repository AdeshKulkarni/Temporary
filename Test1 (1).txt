This error occurs because Spring Boot's default auto-configuration for Jackson (ObjectMapper) was either disabled, overridden by a custom library (such as your internal common-utilities), or failed to initialize early enough for your services to use it.
To fix this permanently, you must explicitly define an ObjectMapper bean in your configuration. Since your application heavily relies on LocalDate and LocalDateTime in its DTOs, it is critical to register the JavaTimeModule so Jackson knows how to serialize and deserialize dates.
The Fix: Create JacksonConfig.java
Create a new configuration class named JacksonConfig.java inside your com.fincore.VoucherService.config package.
package com.fincore.VoucherService.config;

import com.fasterxml.jackson.databind.DeserializationFeature;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.SerializationFeature;
import com.fasterxml.jackson.datatype.jsr310.JavaTimeModule;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Primary;

@Configuration
public class JacksonConfig {

    @Bean
    @Primary
    public ObjectMapper objectMapper() {
        ObjectMapper mapper = new ObjectMapper();
        
        // 1. Required to process Java 8+ LocalDate and LocalDateTime
        mapper.registerModule(new JavaTimeModule());
        
        // 2. Prevent crashes if the frontend sends unexpected JSON fields
        mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);
        
        // 3. Format dates as ISO-8601 strings (e.g., "2026-08-04T11:30:00") instead of timestamp arrays
        mapper.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
        
        return mapper;
    }
}

Why this works:
 * @Primary: This tells Spring that if multiple Mappers exist in the background, this is the absolute master one it should inject into VoucherCommandService (and your Redis Cache configurations).
 * Initialization Sequence: Creating an explicit @Bean forces Spring's Dependency Injection container to construct the ObjectMapper before attempting to construct VoucherCommandService.
