1. Purpose 

The purpose of the Currency Rate Change module is to enable administrators to manage and update the exchange rates for various currencies used within the Fincore system. This ensures that all transactions rely on bank-defined, up-to-date currency rates. 

 

2. Scope 

This functionality covers the user interface and backend logic for viewing, editing, and tracking currency exchange rates. It includes defining data entry rules for the currency rate field, tracking update history, and managing the dual-tab interface.

4. Functional Flow 

4.1 Normal Flow (Successful Currency Rate Update) 

User Action: An administrator navigates to the "Currency Rate Change" page (defaulting to the "Manage Currency Rate" tab). 

System Response: The table loads with current rates. 

User Action: The user clicks the Edit (Pencil) icon for a specific currency (e.g., USD). 

System Response: An "Edit Currency Rate" modal appears. The "Currency Name" field is disabled and pre-filled with "USD". The "Currency Rate" field is enabled for input. 

User Action: The user enters a new rate (e.g., 89.500000) and clicks "Save". 

System Process: Client-side validation runs (ensuring 6.6 format, numeric only). Data is sent to the backend API (/update-rate). 

System Response (Success): The modal closes, the main table refreshes, the new rate is displayed, and the "Last Updated" date is changed to the current date. A success message is displayed ("Currency rate updated successfully"). 

 

 

4.2 Alternate Flows and Conditions (History View) 

User Action: The user clicks the History icon for a specific currency. 

System Response: A side panel or new modal opens, displaying filters (e.g., "Month" dropdown) and a historical log of rate changes for that currency, showing how much the rate changed on specific dates. 

 

5. Error Handling 

Specific, user-friendly error messages will be displayed inline with the relevant field in the edit modal. 

Error Condition 

Message Displayed

Currency Rate format invalid 

"Rate must be a numeric value up to 6 decimal places (e.g., 89.000000, 123456.123456)." 

Non-numeric input in Rate field 

"Currency Rate accepts digits and decimals only." 

 

6. Security Requirements 

Access Control: Access to view and modify currency rates must be restricted only to authorized users with "Currency Master Management" permissions (e.g., finance administrators). 

Data Validation: Strict backend input sanitization and validation must occur on all input fields (especially the Currency Rate field) to prevent SQL injection, XSS vulnerabilities, and ensure data integrity. 

Audit Trail: All successful rate update actions, including the old rate, the new rate, who made the change, and the timestamp of the change, must be securely logged for auditing purposes. 

Confidentiality: All communication between the client (web browser) and the server APIs must be encrypted using HTTPS/TLS protocols. 

 

 

7. Acceptance Criteria 

Admins must be able to view all current exchange rates in the "Manage Currency Rate" tab, adhering to the specified 3-letter currency code and 6.6 rate format. 

The system must prevent updates if the new currency rate input does not meet the specified numeric and decimal place validation rules. 

Upon a successful rate update via the "Edit" action, the "Last Updated" column must reflect the current system date. 

The "Currency Name" field within the "Edit" modal must remain non-editable (disabled) during the update process. 

The "History" action must correctly display a filterable history of rate changes for the selected currency. 

Users must be able to switch successfully between the "Manage Currency Rate" and "My Requests" tabs.
