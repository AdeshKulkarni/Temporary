Here is a unique, enterprise-grade design problem that perfectly isolates the need for both a Factory (to encapsulate complex creation logic) and a Strategy (to encapsulate interchangeable algorithms).
🕰️ LLD Interview Question: Autonomous Drone Delivery System
Time Allotted: 60 Minutes
Context:
You are designing the flight routing module for "AeroDrop," a startup that uses autonomous drones to deliver everything from hot meals to emergency medical organs.
When a drone is dispatched, it must calculate a flight path. However, the algorithm used to calculate this path changes drastically based on what the drone is carrying (Payload) and the current environment.
Functional Requirements:
 * The system receives a DeliveryRequest. This request contains a Source (lat/long), Destination (lat/long), PayloadType (MEDICAL, FRAGILE, STANDARD), and current WeatherCondition (CLEAR, WINDY, RAIN).
 * The system must calculate and return a FlightPath object based on the following algorithmic rules:
   * Medical Payloads: Must calculate the absolute shortest distance, ignoring battery efficiency and residential noise restrictions.
   * Fragile Payloads (e.g., Glassware/Chemicals): Must calculate a path with minimal elevation changes and strictly avoid high-wind zones.
   * Standard Payloads: Must calculate the most energy-efficient path to save battery, strict adherence to residential noise limits.
 * The Twist (Why you need a Factory): The logic to choose the correct routing algorithm is complex and external. For example: If a Standard Payload is requested during RAIN, the system might upgrade it to use the Fragile/Stable routing algorithm for safety. The DispatchController (your client code) should not contain any of this complex mapping or if/else logic.
Expected Entities / Inputs:
You can assume the following enums/classes exist (you don't need to write the complex math, just print statements to represent the algorithm execution):
 * enum PayloadType { MEDICAL, FRAGILE, STANDARD }
 * enum Weather { CLEAR, WINDY, RAIN }
 * class DeliveryRequest (Source, Destination, PayloadType, Weather)
 * class FlightPath (List of Waypoints)
Your Task:
Design and implement the object-oriented structure for this system using the Strategy Pattern (for the routing algorithms) and the Factory Pattern (to encapsulate the creation/selection of the strategy based on Payload and Weather).
Provide the code for:
 * The Strategy Interface and Concrete Strategies.
 * The Factory.
 * The DispatchController (Client) that receives a DeliveryRequest and returns a FlightPath.
